# Forensic Topology Audit — Sovereign Translator, Dictionary & Learning Cloud
**Date:** 2026-11-21  
**Scope:** `vervenveda/Khaemenes_Linguistics.github.io` public translator/dictionary/runtime; separate `artist1970/creative-spark.github.io` local encrypted vocabulary writer.  
**Audit method:** read-only inspection of exact `main` source via GitHub connector, review of current named audits and test source; previous owner-observed results retained as historical. **No browser execution, GitHub Actions success claim, private archive read or ciphertext write in this audit.**

## Source-of-truth topology

1. Canonical educational dataset: `data/sovereign-dictionary.v1.json` has **434 source records**, **397 definitions**, **37 translation-only bilingual records**, and **553 creative vocabulary items**, with **234 related-term links** recorded through the interlingual core's thesaurus statistics.
2. Browser effective dictionary: `assets/sovereign-dictionary.generated.js` is loaded **before** `assets/sovereign-dictionary-v1-errata.js`; the latter corrects bilingual-only metadata and translation trust boundaries to make the effective browser dataset equal to canonical JSON. `scripts/audit-dictionary.mjs` compares canonical and effective bundled content after both scripts run. Merely loading the generated asset without errata can yield divergent editorial metadata.
3. `assets/khaemenes-interlingual-core.js` exposes exact bilingual lookup, reviewed browser-library lookup, dictionary search, definition lookup, thesaurus, local drafts/export/import and stats. Its matching hierarchy is reviewed browser-local pair first, then source bilingual vocabulary draft, then curated campus phrase draft. Missing translation stays missing; no non-English pivot guessed.
4. `apps/translator.html` loads dictionary, errata, lexicon expansion, core, transliteration, review policy and Teacher lab in source order, followed by application code. The page also loads the shared translator loader `assets/khaemenes-translator-loader.js`. Its offline lookup function rechecks browser-local reviewed pairs before consulting the shared core. Online mode calls `https://api.mymemory.translated.net/get` after consent; the machine-generated output is a draft and should require explicit human review before saving.
5. `assets/khaemenes-review-policy.js` controls manually reviewed record creation and import-as-draft defaults, with the explicit reviewed-import trust choice and prototype-key guard. Browser-local approved library uses `khaemenes_interlingual_library_v2`; online cache uses `khaemenes_interlingual_cache_v2`; user dictionary drafts use `khaemenes_dictionary_drafts_v1`. These are **not** the private encrypted cloud.
6. `assets/khaemenes-translation-candidate-lab.js`, `khaemenes-translation-teacher-arbiter.js` and `khaemenes-translation-candidate-ui.js` provide off-by-default, short-text, memory-only candidate observation, 240-record limit, bounded feedback ±0.12 and advisory WITHHOLD/SUGGEST_FOR_REVIEW. No automatic dictionary promotion.
7. The **separate** private Creative Spark `integrations/linguistics-vocabulary/mac-local-terminal.mjs` binds `127.0.0.1:18722`, reads two owner Keychain secrets, source-pins an approved, distinct `apps/vocabulary-mini-cloud/index.html`, serves same-origin local resources under strict CSP, pairs an owner browser, and uses `github-vault-writer.mjs` for private ciphertext-only GitHub records. There is **no authenticated bridge** between the public Translator's browser-local reviewed library and that service; the public page cannot be assumed to write into the owner's vault.
8. Public ecosystem registry `vervenveda/vervenveda.github.io/ecosystem/master-ecosystem-directory.json` now has exactly one canonical `ling-sovereign-translator` entry pointing to `https://vervenveda.com/Khaemenes_Linguistics.github.io/apps/translator.html`. This is directory navigation, not data or identity synchronization.

## Five bubbles

### Bubble 1 — stale or mismatched online translation result (HIGH; real code race)

**Evidence:** `apps/translator.html` `translateOnline()` snapshots `from,to,text`, awaits a network `fetch`, then writes the response to `els.output` and invokes `afterTranslation()`. But `afterTranslation()` creates `reviewSnapshot` using the **current** `els.input.value`, `els.from.value` and `els.to.value`, not the request snapshot. The source has no request epoch/abort guard that prevents an older response from being displayed after switching languages, clearing text or starting a newer request. The review UI can therefore present a result with a false source-language association. No browser exploitation claim is needed to identify this control-flow gap.

**Fix:** Add a monotonic request ID and `AbortController`; cancel pending online requests on mode/language/text/clear changes, and check epoch, captured source, language pair and consent before updating output/cache/review. Ensure late responses cannot populate candidate learning or be saved under the wrong pair. Tests: two out-of-order responses, input edit while pending, language switch, service switch, Clear, invalid/failed provider response.

### Bubble 2 — unexpired browser-local online translation cache (HIGH privacy)

**Evidence:** `cacheKey(from,to,text)` includes the complete source text; `setCache()` writes `cache.entries` to `localStorage`, bounded to 120 records but with no expiration. A successfully consented translation can persist in origin-local browser storage after the online-consent session ends. `clearCacheBtn` is present and works by removing the key, but cleanup is entirely manual. This is separate from the encrypted mini-cloud. `GET` requests to MyMemory also include source text in the URL after explicit consent; that provider exposure remains a separate disclosed risk.

**Fix:** Default machine-draft cache to in-memory only unless the user explicitly opts into persistent local drafts; or use short TTL, visible retention policy, clear-on-session/revocation and safe metadata-free keys. Preserve reviewed library records independently; never silently delete them. Tests: session expiry, cache disabled, consent reset, no sensitive text in persistent keys, explicit opt-in persistence, manual clear.

### Bubble 3 — canonical dictionary depends on a post-load errata overlay (MEDIUM build/sync)

**Evidence:** `docs/SOVEREIGN_DICTIONARY_STATUS.md` and `docs/SOVEREIGN_LEXICON_REVIEW_CONTRACT.md` acknowledge that `assets/sovereign-dictionary.generated.js` is behind `data/sovereign-dictionary.v1.json`. `assets/sovereign-dictionary-v1-errata.js` patches translation-only definitions and editorial statuses at load time. The current `scripts/audit-dictionary.mjs` verifies equality **after** the errata, not the generated bundle alone.

**Fix:** Regenerate the browser JS directly from canonical JSON with deterministic, no-dependency build tooling, compare the unpatched generated object byte/structure to canonical, and only then retire the overlay and update all references/cache version in one reviewed change. Test 434/397/37/553 counts, 234 source-linked relationships, 148 bilingual source pairs, source attribution and both reverse/forward exact lookup. Keep errata until whole-site consumers and service-worker caches are audited.

### Bubble 4 — candidate provenance and certainty are weaker than review contract (MEDIUM learning)

**Evidence:** `afterTranslation()` forwards source and translation to `KhaemenesTranslationCandidateTeachingUI.capture()` with generic `origin:"public-ui"` and no field identifying whether the suggestion was an offline dictionary source, browser-reviewed pair, campus draft, online MyMemory result or cached machine draft. Candidate scoring rewards repeat observations and matches with shared lookup and applies capped feedback, but the source trust tier and independent correctness verification are not present in the observation record. Its current PII filter rejects some obvious strings but does not prove that a phrase lacks personal data.

**Fix:** Introduce a typed minimal evidence contract (`providerTier`, source ID/revision, consent category, review outcome, language pair, freshness) with provenance-preserving status; exclude private/learner contexts, raw page harvesting and secrets; separate *frequency* from *confidence* and never boost accuracy from repeat machine outputs alone. Retain laNGgwij-inspired WITHHOLD threshold 0.48, margin 0.06, bias cap ±0.12 until validated against labelled translation examples. Tests: conflicting sources, repeated wrong machine answer, private input denial, reviewed feedback, output clear, provenance rendering.

### Bubble 5 — no owner-authorized durable sync from reviewed dictionary to encrypted Mac vault (ARCHITECTURAL GAP)

**Evidence:** The public Translator saves reviewed pairs to browser `localStorage`; its export/import features are manual JSON files. The separate Creative Spark Mac-local vault expects paired, authenticated ciphertext API calls from its *approved private local HTML client* and is not a published public website endpoint. `docs/TRANSLATION_CANDIDATE_TEACHER_SYNC_2026-11-21.md` explicitly states that there is no live bridge. This is **not** evidence of missing or deleted archive records; it is missing cross-system functionality.

**Fix:** Design an **explicit user-selected reviewed-pair export** with redaction/minimization and deterministic schema, and a separate owner-authorized import review inside the paired local vocabulary application. Encrypt in browser, honor existing revision/CAS/no-clobber rules, require stable HMAC identity, preserve ciphertext, and never connect arbitrary public pages directly to Keychain or auto-upload Teacher candidates. Tests: no opt-in, malformed pack, duplicates, identity mismatch, read-only preview, owner approval, revision conflict, encrypted write and exact readback, restore/rollback. Keep STOS T01/T02/T03 out of scope.
